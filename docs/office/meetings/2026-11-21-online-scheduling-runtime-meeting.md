# 온라인 기반 프로젝트의 예약 실행 방식 회의

## 의제

프로젝트가 온라인 기반이라는 사용자 전제를 운영 규칙에 반영하고, 로컬 crontab과 Codex 예약 자동화가 제품 운영 스케줄러를 대신할 수 있는지 구분합니다.

## 근거와 구분

- **사용자 전제:** “우리 프로젝트는 online 이야.”
- **도구 동작:** 이 Codex 환경의 cron 자동화는 로컬 실행 환경의 특정 프로젝트를 대상으로 하는 예약 작업입니다. 이는 외부에 항상 연결된 제품 서버의 예약 실행을 보장하지 않습니다.
- **기술적 구분:** 개인 컴퓨터의 crontab은 해당 컴퓨터의 실행 환경에 묶입니다. 온라인 서비스의 운영 예약 작업은 선택된 호스팅 실행 환경에서 돌아야 합니다.
- **미결정:** 제품의 구체적인 예약 작업, 호스팅 제공자, 실행 주기, 인증 정보, 재시도·실패 처리, 비용/관측 요구사항은 정해지지 않았습니다.
- **범위 제외:** 이번 회의는 스케줄러를 고르거나 실제 예약 작업을 생성·활성화하지 않습니다.

## 취합 결론

1. **채택된 원칙:** 프로젝트는 온라인 기반입니다. 운영 예약 작업은 사용자의 로컬 컴퓨터나 로컬 Codex 세션에 의존하지 않도록 합니다.
2. **선택 보류:** 실제 스케줄러와 제공자는 예약 작업·호스팅 환경·보안·오류 처리·비용 요건을 정한 뒤 선택합니다.
3. **Codex 자동화의 범위:** 로컬 예약 기능은 개인 개발 보조에 사용할 수 있지만, 온라인 제품 서비스의 상시 실행 수단으로 보지 않습니다.
4. **실행 상태:** 예약 작업, 스케줄러, 외부 설정은 생성·변경·활성화하지 않았습니다.
5. **도입 단계:** 1단계 GitHub→Slack 알림은 부분 검증 상태 그대로입니다. 이 운영 원칙은 2~4단계가 구현됐다는 뜻이 아닙니다.

## 사용자 결과 수락

커튼 뒤(사용자)는 “우리 프로젝트는 online 이야 이건 회의록에 기록해 두고 결과 수락”이라고 응답했습니다. 이 응답은 온라인 기반 원칙의 문서화 결과를 수락한 것입니다. 특정 스케줄러 선택이나 예약 작업 실행을 승인한 것은 아닙니다.
