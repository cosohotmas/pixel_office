# PRD: 현재 위치 기반 대화형 날씨 서비스

## 1. 문서 목적

사용자가 앱 또는 웹앱을 열고 “오늘 날씨 알려줘”라고 입력하거나 말하면, 현재 위치를 기준으로 신뢰할 수 있는 날씨와 행동 정보를 빠르게 제공한다.

## 2. 문제 정의

사용자는 날씨를 확인할 때 앱을 열고 위치를 검색하거나 여러 화면을 이동해야 한다. 단순한 질문에 비해 확인 과정이 길고, 현재 위치와 실제 활동에 맞는 정보가 분산되어 있다.

## 3. 목표와 성공 지표

### 목표

- 첫 화면에서 사용자가 날씨 확인 방법을 즉시 이해한다.
- 위치 승인 후 한 번의 질문으로 오늘 날씨를 확인한다.
- 날씨 수치보다 외출 판단에 도움이 되는 정보를 제공한다.

### MVP 성공 지표

- 위치 승인 후 첫 날씨 응답까지 10초 이내
- 신규 사용자의 첫 질문 완료율 70% 이상
- 날씨 결과 화면에서 생활 안내 확인율 50% 이상
- 오류·위치 불일치 신고율 5% 이하

## 4. 대상 사용자

출근·등교·외출 전에 빠르게 날씨를 확인하려는 사람. 특히 날씨 앱의 복잡한 메뉴보다 질문과 즉답을 선호하는 사용자다.

## 5. 핵심 사용자 스토리

> 외출 전 사용자인 나는 현재 위치의 오늘 날씨를 빠르게 알고 싶다. 그래서 앱을 열고 자연어로 질문하면 기온, 강수확률, 미세먼지와 적절한 준비물을 한 화면에서 확인하고 싶다.

## 6. 기능 요구사항

### P0 — MVP 필수

- 위치 권한 요청과 현재 위치 확인
- 기상청 날씨 데이터 연동
- 현재 기온·하늘 상태·강수확률·체감온도 표시
- 오늘 시간대별 예보 표시
- 현재 위치 지도 표시
- “우산이 필요해요”, “외투를 입을까요?” 같은 생활 안내
- 위치 권한 거부·데이터 오류·위치 불일치에 대한 안내

### P1 — 다음 단계

- 텍스트 자연어 질문의 의도 분류
- 음성 입력
- 미세먼지와 대기질 표시
- 즐겨찾는 장소 등록
- 알림 및 출발 전 요약

## 7. 비기능 요구사항

- 위치 데이터는 사용자 동의 후 사용한다.
- 필요한 위치 정보만 수집하고 서비스 목적과 보관 정책을 명확히 안내한다.
- 날씨 데이터의 기준 시각과 출처를 표시한다.
- 모바일 화면을 우선 설계하고 웹앱에서도 동일한 핵심 흐름을 제공한다.

## 8. 기본 화면 흐름

`앱 실행 → 위치 권한 안내 → 권한 허용 → 질문 입력/음성 시작 → 날씨 응답 → 지도·예보·생활 안내 확인`

## 9. 제외 범위

MVP에서는 장기 기후 분석, 전문 기상 분석, 다중 사용자 공유, 복잡한 소셜 기능을 만들지 않는다.

## 10. 리스크와 대응

| 리스크 | 대응 |
|---|---|
| 위치 권한 거부 | 장소 직접 입력으로 대체 |
| 날씨 데이터 지연 | 기준 시각 표시와 재시도 제공 |
| 자연어 오인식 | 질문 예시와 수정 버튼 제공 |
| 지도·기상 위치 불일치 | 행정구역명과 좌표 기준을 함께 표시 |

## 11. 완료 기준

사용자가 위치를 허용한 뒤 “오늘 날씨 알려줘”를 입력하면, 현재 위치의 날씨·시간대별 예보·생활 안내·지도 위치를 한 화면에서 확인할 수 있어야 한다.
